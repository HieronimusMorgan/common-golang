# V3 integration guide

Additive APIs; no Asset Management business tables or roles are automatically installed. Apply `migrations/002_v3.sql` after `001_common.sql` in each relevant service database. For RLS, adapt `examples/sql/tenant_rls.sql`, test using a non-owner non-BYPASSRLS runtime role, and use `database.WithinScopedTx(ctx,db,nil,fn)`. Use `idempotency.ExecuteScoped` for deduplicated scoped business commands. All repository operations must use the provided transaction; direct database access bypasses this helper. Cross-branch transfer authorization and service-specific RLS policies remain application responsibilities. `scope.Key` creates a collision-safe hashed tenant/branch/resource tuple; actor scoping is optional for shared data and mandatory where access differs by user. `database.RetryableTransactionError` only classifies definitive SQLSTATE aborts, not ambiguous commits. Retry only an idempotent transaction callback.

## Events and workers

Create `event.New(ctx,type,version,source,aggregate,payload)`, validate and marshal it, enqueue via `outbox.Enqueue` in the same business transaction. Keep serialized envelope within the legacy outbox's 1 MiB cap. Consumer `nats.InboxHandler(db,consumer,authorize,handler)` validates the envelope, invokes the trusted source/tenant policy, and calls `inbox.Process`. `Consume` acknowledges only after handler success. The handler must use the supplied transaction for all effects; external side effects require a further outbox. Inbox dedupe keys are consumer/source/event ID and compare a fingerprint; producers must send an identical envelope on retries. Broker ACLs and the authorize function establish trust; event contents alone do not establish identity. No exactly-once delivery guarantee. Configure broker MaxDeliver and DLQ policy; explicit aggregate ordering and schema registry remain external.

Leased outbox: stop all legacy `RunOne` workers before enabling `ClaimBatch`. Apply migration 002. Claim a bounded batch, publish with a durable JetStream acknowledgement and stable ID, then `Complete` with claim token. Set lease duration greater than worst-case batch processing and acknowledgement time, or use concurrency to bound processing. Claims count attempts even when a worker crashes; expired claims are reclaimable until max attempts. A slow publisher may still duplicate delivery; inbox is mandatory. `Redrive` is privileged, manual and must retain deduplication records across replay windows. `worker.Pool` is bounded execution for channel jobs, not a durable job queue. Cancellation can abandon dequeued jobs; use durable claims for business operations. `scheduler.Run` provides fixed-delay non-overlap within one process and accepts a caller-owned lease adapter; it is not calendar cron or cluster-wide exactly-once scheduling. Callback cancellation is cooperative.

## Authentication / authorization

`jwt.NewJWKS` accepts a fixed trusted HTTPS endpoint, cache TTL (1s–1h), optional transport and `auth.Revocations`. RS256 only. No redirects, token-supplied URLs or unknown-kid forced refresh. Publish keys before rotation and allow the TTL to elapse. Cached keys can continue validating until expiry; revoke compromised sessions via a fail-closed adapter. `middleware.Authenticate` prefers `VerifyContext` when available. `redis.Client` implements revocation lookup and marking; require persistent no-eviction storage and include JWT leeway in the revocation lifetime. `auth.NewRefreshToken` returns raw opaque token and digest, never log raw tokens; authentication service must implement atomic rotation, reuse detection, expiry and session storage. `rbac.Require` enforces selected scope before calling an explicit policy; roles resolved from server-provided assignments. No default service-to-service policy or KMS signer supplied.

## Observability

`observability.NewHistogram` exposes a static-name cumulative Prometheus histogram (seconds); do not expose metrics publicly. `observability/otel.New` configures a private OTel tracer provider with OTLP HTTP export (full URL including `/v1/traces`), sampling, W3C TraceContext and explicit shutdown. Wrap HTTP transport/server with static route labels, use `WithLog` to include trace and span IDs. For NATS, pass headers via `Inject`/`Extract` using an appropriate carrier and trusted broker. Instrument SQL/Redis explicitly with spans; no automatic instrumentation is claimed. OTLP endpoint TLS by default, insecure allowed only with explicit opt-in. OTel adapter compile and collector export remain unverified here.

## Redis and cache

`cache.New[T](redisClient,redis.ErrMiss,timeout,maxInflight)` coalesces same-key misses in a process and applies TTL jitter. It does not coordinate cache stampedes across replicas. First caller cancellation affects shared load; treat values as immutable and use scoped cache keys. `redis.AllowTokenBucket` uses Redis server time and versioned policy names. `TryFencedLock` uses a separate lock namespace from `TryLock`; downstream resources must reject stale fences. Redis sequence counters can roll back on failover or restore; use durable SQL fencing for correctness-critical operations. Cluster/Sentinel topology adapters and sliding windows remain future work; legacy Raw() signature retained.

## Storage

Construct official MinIO SDK client using credentials from environment or provider, not committed secrets; configure TLS and a private bucket. Wrap `storage/minio.Provider{Client: sdkClient, Bucket: name}` in `storage.Client` with max bytes and explicit MIME allowlist. Keys are tenant/branch scoped; authorize resource ownership in business logic before calling. Upload stages a private temp file, enforces size, MIME sniffing and optional expected SHA256; this is not malware scanning or a quarantine workflow. Backend SDK handles multipart upload. Presigned GET URLs are bearer capabilities; do not log them, keep TTL short. Adapter compilation/live integration requires external dependencies. Upload cancellation depends on the underlying reader; limit concurrency and temporary disk capacity.

## Audit and retention

`audit.Snapshot` includes only explicitly allowlisted top-level scalar fields. Never allow sensitive fields; `Seal`/`Verify` HMAC protects event fields and change payload, not database timestamp or record deletion. `AppendChange` writes signed text data with key ID in the same transaction. Keep HMAC keys outside DB. Revoke UPDATE/DELETE/TRUNCATE for runtime role (see RLS example); privileged owners can still modify data. Retention `PurgeBatch` requires reviewed cutoff and deletes only published outbox, inbox or completed idempotency rows. Do not delete dedupe records within business/broker replay windows. Audit deletion/export and legal retention are explicit organizational policies.

## Config and flags

`config.Load(defaults, lookup, validate)` reads tagged environment values, falling back to tag defaults; nested value structs supported. `config.JSON` overlays JSON on defaults separately; when combining, use `JSON` then `Load` and avoid tag defaults that override JSON fields. `config.Snapshot[T]` publishes complete values atomically; do not mutate maps/slices after publishing. No file watcher or external secret backend. `featureflag.New` copies rules and evaluates branch override > tenant > default with stable subject-based basis-point rollout (10000 = all). Flags never grant permissions.
